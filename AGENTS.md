# Project Intelligence for Agents

This document provides context and guidelines for AI coding agents working in the `agent-conductor` repository.

## 🛠 Commands

### Build & Execution
- **Build**: `make build` (builds `conductor` to project root)
- **Run**: `go run ./cmd/conductor/main.go` (Expects `project.yaml` in working directory)
- **Scaffold**: `go mod tidy` (ensure dependencies are clean)

### Testing
- **Run All Tests**: `go test ./...`
- **Run Package Tests**: `go test ./internal/scanner`
- **Run Single Test**: `go test -v -run TestName ./internal/database`
- **Test with Coverage**: `go test -coverprofile=coverage.out ./...`

### Database (sqlc)
This project uses `sqlc` to generate type-safe Go code from SQL.
- **Generate Code**: `sqlc generate`
- **Workflow**:
    1. Modify `sql/schema.sql` (schema) or `sql/queries.sql` (queries).
    2. Run `sqlc generate`.
    3. Use the updated methods in `internal/database`.

### Linting & Formatting
- **Format**: `go fmt ./...`
- **Vet**: `go vet ./...` (checks for common mistakes)
- **Static Check**: `golangci-lint run` (if installed)

## 🏗 Architecture & Project Structure

- `cmd/conductor`: The main CLI entry point. Uses Cobra for command-line parsing.
- `internal/config`: Configuration loading from YAML (uses `gopkg.in/yaml.v3`).
- `internal/database`: Database access layer generated by `sqlc`. Includes `DBTX` interface for transactions.
- `internal/scanner`: Monitors the `inbox/orders` directory for new work orders using `fsnotify`.
- `internal/queue`: Manages task state and atomic claiming of work.
- `internal/executor`: Handles running external agents (e.g., via `opencode`).
- `internal/worker`: The main execution loop that processes tasks from the queue.
- `sql/`: Contains the SQL source of truth for the SQLite database.
- `docs/`: Technical specifications and implementation plans.

## 🎨 Code Style Guidelines

### 1. General Principles
- Follow **Effective Go** and standard Go idioms.
- Keep functions small and focused.
- Favor composition over inheritance (standard Go).
- Document exported functions only if the logic is complex or non-obvious.

### 2. Naming Conventions
- **Packages**: Short, lowercase, single word (e.g., `config`, `scanner`).
- **Exported Types/Funcs**: `PascalCase`.
- **Unexported Types/Funcs**: `camelCase`.
- **Receivers**: 1-3 letter abbreviations (e.g., `s *Scanner`, `cfg *Config`).
- **Variables**: Descriptive but concise. Use `err` for errors, `ctx` for context.

### 3. Imports
Group imports into three blocks separated by newlines:
1. Standard library imports
2. Third-party library imports
3. Internal project imports (`github.com/ponchione/agent-conductor/...`)

Example:
```go
import (
	"context"
	"fmt"

	"github.com/google/uuid"
	"gopkg.in/yaml.v3"

	"github.com/ponchione/agent-conductor/internal/config"
)
```

### 4. Error Handling
- **Never ignore errors**: Always check `if err != nil`.
- **Wrap errors**: Use `fmt.Errorf("context: %w", err)` to provide traceability.
- **Return early**: Use the "guard clause" pattern to minimize nesting.
- **Sentinel Errors**: Define them at the top of the file for common error states.

### 5. Context & Concurrency
- **Context First**: Always pass `context.Context` as the first argument to functions performing I/O, network calls, or long-running tasks.
- **Timeouts**: Respect context deadlines.
- **Synchronization**: Use `sync.Mutex` for protecting shared state (see `internal/scanner`).
- **Graceful Shutdown**: Listen for `SIGINT` and `SIGTERM` in `main.go` and pass the context down.

### 6. Logging
- Use `log/slog` for structured logging.
- Prefer attributes over formatted strings for metadata:
  `slog.Info("processing file", "path", path, "repo", repo)`
- Use appropriate log levels: `Debug` for noise, `Info` for progress, `Warn` for recoverable issues, `Error` for failures.

### 7. Database Patterns
- Use `internal.database.DB` as a wrapper around `*Queries` for business-level DB logic.
- Use `WithTx` for atomic operations involving multiple queries.
- Do NOT manually edit files in `internal/database` that have the `sqlc` header.
- Always use `context.Context` with DB methods.

### 8. Configuration
- Add new configuration parameters to `internal/config/config.go`.
- Ensure defaults are set in the `Load` function.
- Use `yaml` struct tags.

## 🛡 Safety & Guardrails
When implementing features, adhere to the safety limits defined in `project.yaml`:
- `MaxDepth`: Prevents infinite recursive task spawning.
- `MaxFilesChanged`: Limits the blast radius of an agent.
- `MaxTaskDurationMinutes`: Ensures tasks don't hang indefinitely.
- **Forbidden Paths**: Always respect the `forbidden_paths` list in `RepoConfig`.
