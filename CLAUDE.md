## Architecture

Agent Conductor orchestrates AI coding agents across repositories via a 3-phase pipeline. Work orders (Markdown files) are dropped in `inbox/orders/`, detected by the scanner, and processed through Scope → Build → Verify phases.

**Data flow:**
1. `internal/scanner` (fsnotify) detects `inbox/orders/*.md` → creates `workflows` + initial `scope` task in SQLite
2. `internal/queue` atomically claims tasks for workers, enforcing safety budgets (depth, file count, duration)
3. `internal/worker` executes phases:
   - **Scope**: parses work order YAML → assembles repo context → calls local LLM → writes `context_package.json`
   - **Build**: runs `opencode` CLI with work order + context package → agent modifies files + commits
   - **Verify**: gets git diff vs main → calls local LLM → writes `verification_report.json` → sets workflow to `human_review`

**Key packages:**
- `cmd/conductor/main.go` — entry point; wires all components together
- `internal/config` — loads `project.yaml` into `ProjectConfig`
- `internal/database` — SQLite via `modernc.org/sqlite`, code-generated by `sqlc`; tables: `workflows`, `tasks`, `events`
- `internal/git` — go-git wrapper for branch creation, commits, diffs
- `internal/llm` — OpenAI-compatible client for local models (Ollama/llama)
- `internal/context` — assembles repo structure, git history, and file content for LLM prompts
- `internal/executor` — shells out to `opencode` CLI with timeout handling
- `internal/templates` — system prompts for each LLM phase

## Configuration

Per-project config lives in `project.yaml` (not the old `config.yaml`). Key sections: `project` (name/path/language), `index` (include/exclude globs), `conventions` (path hints for context assembly), `local_model` (endpoint/model), `safety` (forbidden_paths, budget limits), `git` (branch prefix, author).

## Database

Schema is in `sql/schema.sql`, queries in `sql/queries.sql`. After changes, run `sqlc generate` to regenerate `internal/database/`. Use the `DB` wrapper and `WithTx` for transactions. Workflow states: `pending → scope_complete → build_complete → human_review → completed/failed`.

## Code Style

- Receivers: 1–3 letter abbreviations (e.g., `s *Scanner`, `q *Queue`)
- Imports: 3 groups — stdlib, third-party, internal (`agent-conductor/internal/...`)
- Errors: always check; wrap with context; use guard clauses (early return on error)
- Logging: `log/slog` with structured attributes
- Context (`context.Context`) as first argument on all I/O operations

## What's Not Yet Implemented

GitHub PR creation, cross-repo ticket routing, full CLI interface (cobra skeleton only), and human approval gate resume flows are planned but incomplete. The `internal/llama` directory is untracked/experimental.
