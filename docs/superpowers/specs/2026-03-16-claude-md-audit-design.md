# Log CLAUDE.md Contents Into Pipeline Run Metadata — Design

## Goal

Record the target project's CLAUDE.md contents at build start so operators can
audit what instructions Claude Code was silently loading during the build phase.

## Architecture

A single nullable TEXT column (`build_claude_md_content`) is added to the
existing `pipeline_runs` table. The worker reads the file before invoking the
executor and stores the result alongside the existing build metrics. The status
CLI shows a presence indicator without dumping the full contents.

## Data Layer

### Schema change

Add to `pipeline_runs` in `internal/database/schema.sql`:

```sql
build_claude_md_content TEXT
```

Positioned after the existing `build_tool_calls` column in the "Build
enrichment" section. Nullable: NULL means "not captured" (old rows) or "file
absent." An empty string means the file exists but is empty (distinct from
absent, though unlikely in practice).

### SQL queries

**Extend `UpdatePipelineRunBuild`** in `sql/queries.sql` to include
`build_claude_md_content = ?` in the SET clause, after `build_tool_calls = ?`.
After regeneration, `UpdatePipelineRunBuildParams` will gain a new
`BuildClaudeMdContent sql.NullString` field. The call site in `build.go` must
populate it.

**Add `GetPipelineRunByWorkflowID`** — a new `:one` query that returns
`build_claude_md_content` by `workflow_id`. Returns a useful column subset (id,
build_claude_md_content) rather than `SELECT *`, but is named generically so it
can be widened later without a rename. Used by the status command. Add a
corresponding row type alias in `aliases.go`.

### Code generation

Run `sqlc generate` to regenerate `internal/database/dbgen/`. Never hand-edit
files in that directory.

### Aliases

Add any new param/row type aliases to `internal/database/aliases.go` as needed.

### Migration

Append to the `migrations` slice in `internal/database/database.go`'s `NewDB`
function:

```go
"ALTER TABLE pipeline_runs ADD COLUMN build_claude_md_content TEXT",
```

This follows the existing pattern for `build_cost_usd`, `build_session_id`, and
`build_tool_calls`. The migration runner swallows "duplicate column" errors, so
this is safe to run on databases that already have the column (e.g. fresh DBs
created from the updated schema).

### DB wrapper

Expose the new `GetPipelineRunByWorkflowID` query via the `DB` struct in
`internal/database/database.go`, following the existing delegation pattern.

## Write Path (internal/worker/build.go)

At the top of `runBuild`, before the executor runs:

1. Read `filepath.Join(w.cfg.Project.Path, "CLAUDE.md")` with `os.ReadFile`.
2. If `os.IsNotExist(err)` — leave a `sql.NullString{}` zero value (NULL).
3. If read succeeds — store `sql.NullString{String: content, Valid: true}`.
4. If any other error — log a warning and treat as absent (do not block the
   pipeline).

Pass the value through the existing `UpdatePipelineRunBuild` call at the end of
`runBuild`.

### Constraints

- Only read `CLAUDE.md` from `cfg.Project.Path` root — not `~/.claude/CLAUDE.md`.
- Do not read `CLAUDE.local.md` or subdirectory CLAUDE.md files.
- Do not create or modify the file.
- Use `os.ReadFile` — no recursive directory walking.

## Read Path (cmd/conductor/status.go)

After the existing "ARTIFACTS" section, show a one-liner:

```
CLAUDE.md:      present (1,247 bytes)
```

or:

```
CLAUDE.md:      (none)
```

Uses the new `GetPipelineRunByWorkflowID` query. If the query returns no row
(e.g. old DB, pipeline run not yet created), skip the line silently.

The `stats` command is aggregate-focused and does not need changes. This
satisfies the work order acceptance criterion "accessible via the stats or
status commands" through the `status` path; the `stats` command operates on
aggregates where per-run CLAUDE.md content is not meaningful.

## Compatibility

- **spec-v2:** The observability V2 spec covers server/UI/SSE/React work. It
  reads from `pipeline_runs` but does not modify the schema. Adding a column is
  purely additive. The existing REST endpoints (`/api/sessions`,
  `/api/sessions/:id`, `/api/stats/plan-audit`) do not query
  `build_claude_md_content` and are unaffected.
- **Schema upgrades:** `NewDB` applies `CREATE TABLE IF NOT EXISTS` for fresh
  databases and runs the `migrations` slice for existing databases. The new
  `ALTER TABLE` migration ensures existing DBs get the column.
- **Old rows:** Pre-existing `pipeline_runs` rows will have NULL for the new
  column, which is the correct sentinel for "not captured."
